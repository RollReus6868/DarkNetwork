## Starting on a new Claude account
Nothing from the old account carries over except what is in GitHub and the services themselves (memory, chats, Projects and account skills do not). To get going:

2. The repo's `.claude/skills/` (this skill, `ebook-listing-from-pdf`, `dn-product-studio-dev`) then load for the session.

## Visitor statistics (desktop tool + phone app; migration 0006)
- Google Analytics `G-0EV862YX9Q` is also loaded; the site's own counter is what the tool and app show. No IP is stored. Admin visits and `/admin` are not counted (`enabled` flag in `src/lib/analytics.js`); `/studio` is its own page without the tracker.
- `src/lib/analytics.js` writes with raw `fetch(..., { keepalive: true })` to `/rest/v1/<table>` using the anon key (so rows leave even when the tab closes):
  - `page_view` per route change: path (never the query string: it can hold a download token), `visitor_id` (localStorage `dn_visitor`), `session_id` (localStorage `dn_session`, new after 30 quiet minutes, keeps the landing `utm_*` tags), `country` from Cloudflare's `/cdn-cgi/trace` (`loc=`, asked once per browser, 2-letter code), `referrer`.
  - `site_event` `engage` (ms a page stayed visible, sent on route change / tab hidden, >= 1 s, capped 1 h) and `add_to_cart` (`track()` from `src/lib/cart.js` when a new ebook enters the cart). The table's check constraint only allows these two names.
- `checkout_attempt` (server only, RLS with no policy): `createEbookCheckout` sends `checkout_ref` in Lemon Squeezy custom data and inserts the row after the checkout URL exists (failure never blocks the sale); the webhook marks it `paid` (order_id, email, paid_date) and refund events set `refunded` / `partially_refunded`.
- `public.tool_analytics(p_days)` (SQL, security definer, execute granted only to `service_role`) builds everything in one JSON; `public.traffic_channel(ref, utm_source, utm_medium)` maps sessions to GA channel groups (own domain referrer = Direct). `toolApi` and `adminApp` action `analytics` call it through `asServiceRole.rpc`. Sessions recorded before 12/10/2026 have no session id: they are grouped per visitor per day. "Buy now" skips the cart, so checkouts can exceed add-to-cart.

## Deploy
- Site: commit and `git push origin claude/chuyen-sang-supabase`; Cloudflare rebuilds in a few minutes, then the user hard-refreshes (Ctrl+F5). The dashboard's "New deployment" button is a manual file uploader, not a rebuild: to force a rebuild push a commit (an empty one is fine). To confirm the new bundle is live, fetch the page, find `/assets/main-*.js` (site) or `/assets/studio-*.js` (app) and search it for a string from the change.
- Edge function: `mcp__Supabase__deploy_edge_function` with files named `<fn>/index.ts` plus every `_shared/*.js` it imports (always `backend.js` + `entities.js`; `chat.js` for toolApi/chatAdmin; `stats.js` for toolApi/adminApp; `push.js` for adminApp/chatGuest/lemonSqueezyWebhook), `entrypoint_path` `<fn>/index.ts`, `verify_jwt: false`. File contents must be passed inline: print them with `python3 -c "import json; print(json.dumps([...]))"` right before deploying and paste that. A change in `_shared` only reaches functions you redeploy. A new function also goes into `supabase/config.toml`.
- Database: new migration file in `supabase/migrations/` + `apply_migration`; never edit an applied one. Applied so far: 0001 init, 0002 storage, 0003 hardening, 0004 guest access token, 0005 page views, (tmp_youtube_import, applied once outside the repo), 0006 analytics, 0007 push, 0008 settings_and_accounts. Run `get_advisors` (security) after DDL; "RLS enabled, no policy" on `checkout_attempt`, `push_subscription`, `push_config` and `import_key` is intended.
- Destructive SQL (`delete`, `drop`) through the connector asks the user to confirm and has come back `cancelled` every time, even after the user said yes in chat. Do not retry in a loop: after one cancelled attempt, give the user click-by-click steps (Supabase > Table Editor > table > tick the row > Delete 1 row).
- The project instructions say: ask before publishing. Commit locally, then ask once (AskUserQuestion) before migrations, function deploys and the push; say which payment/chat functions change. When the user's own request already says to put it live ("tự động update", "đưa lên luôn"), that is the approval: do not ask again.
- GitHub shows the Cloudflare check "Workers Builds: darknetwork" as **failure** on every commit since 11/10/2026, yet the dashboard lists each deployment as Ready and the site updates (the Worker's `modified_on` moves a minute after the push). Ignore that red mark; confirm the live bundle instead (Verify live). The Cloudflare connector (`workers_list`) shows `modified_on` only, not build logs.
- Commit messages end with the attribution trailers from the session reminder. `gh` GraphQL is blocked in the sandbox; use `gh api repos/...` (REST).
- A new branch can make the stop hook report false "unpushed commits": add a fetch refspec for it, fetch, and `git branch --set-upstream-to`.

## Verify live
- The sandbox shell cannot reach darknetworkofficial.uk (curl returns 000) and `WebFetch` only sees the title (and invents answers about asset contents: do not trust it for that). Reliable ways: (1) the built-in browser below; (2) from the database: `select net.http_get(url := 'https://darknetworkofficial.uk/?x=' || extract(epoch from now()))`, then `select substring(content from '/assets/main-[A-Za-z0-9_-]+\.js') from net._http_response where id = <id>`; compare with `ls dist/assets` of your own build (same source + `.env.production` gives the same hash), or fetch that asset the same way and test `position('<string from the change>' in content) > 0`. Styles split into `assets/main-*.css` and `assets/src-*.css`: search both.
- `WebFetch` on the domain confirms a page is served (title only; it cannot see rendered content). A deep path such as `/login` returning the page proves the SPA fallback. `https://darknetworkofficial.uk/cdn-cgi/trace` shows `loc=` (the country source).
- Home rows on the live site: in the browser, `[...document.querySelectorAll('[aria-roledescription="carousel"]')]` gives one element per row (`aria-label` = row title); `.dn-book h3` inside are the titles (each list is repeated by `loopSlides` to fill the loop, so dedupe).
- To look at the rendered live site use the built-in browser (`mcp__remote-devices__Claude_Browser__*`) when the session is linked to the user's computer: `preview_start` opens a tab, `javascript_tool` measures the DOM, `read_console_messages` shows errors, `performance.getEntriesByType("resource")` shows load cost. A visit made there counts as a real visitor (Vietnam): mention it. For /studio check the login screen, `/studio/manifest.webmanifest` start_url, `/studio/sw.js` 200 and `navigator.serviceWorker.getRegistration('/studio/')`. Reset with `resize_window` preset desktop.
- Call a live function from the database with `net.http_post(...)` via `execute_sql`, then read `net._http_response`. Expected: `toolApi` without token -> 401; `adminApp` without login -> 401; webhook with a bad signature -> 401 "Invalid signature"; `chatGuest` `{action:'unread', guestKey:'guestkey-healthcheck'}` -> 200 `{unread:0}`; `createEbookCheckout` with a published ebook id -> 200 and a checkout URL (this also writes a `checkout_attempt` row that shows in the tool and app: avoid it, or tell the user to delete it).
- Push health: `select count(*), max(last_ok) from push_subscription` (phones that turned notifications on, and when a notification last reached one).
- `mcp__Supabase__query_logs` (source `function_edge_logs`) shows whether Lemon Squeezy really called the webhook (user agent `LemonSqueezy-Hookshot`) and the status. Logs lag about a minute.
- After a test purchase check `ebook_purchase` joined to `ebook`, that every `secure_file_uri` exists in `storage.objects` for bucket `private-files`, and that the `checkout_attempt` row became `paid`.
- US night = quiet hours: no new `page_view` for an hour is normal; check with your own visit before suspecting a bug.

## Lessons from the migration
- Lemon Squeezy sends checkout custom data in `meta.custom_data`, not `data.attributes.custom_data`. The Base44-era webhook read the wrong place and answered 200 `No ebook_id in custom data`, so no purchase was ever recorded. A 200 from a webhook proves nothing: check the row.
- Lemon.js loaded dynamically (after page load) does not start itself: call `window.createLemonSqueezy()` in the script's onload before using `window.LemonSqueezy`. Without it `Url.Open` never ran, the code fell back to `window.open` after an `await`, and Chrome blocked that as a pop-up. Never open checkout in a new tab after an async step; the fallback is `window.location.assign(url)` (Lemon Squeezy redirects back after payment).
- Apple Pay only appears in Safari (iPhone/iPad/Mac with a card in Wallet); on Windows/Chrome only card, Google Pay etc. show. Not a site bug.
- Lemon Squeezy Test and Live modes are separate: API key, webhook and products must be recreated in Live after store activation (identity review can take days). Settings > Domains there is for hosting the LS storefront on a custom domain: do not connect the site's domain to it. Test card `4242 4242 4242 4242`.
- Stored files are named `<8 hex>_<name>`; the prefix stays in storage for uniqueness and is stripped only in the signed download URL (`download` option in `CreateFileSignedUrl`).
- A `secure_file_uri` or `bonus_secure_file_uri` starting with `mp/private/` is an old Base44 address: the file is NOT in Supabase even though Admin shows "Da co file rieng tu". Re-upload with Admin > Ebooks > Thay file. The desktop tool restores main PDFs only, not bonus files.
- Supabase free SMTP only mails project members, so "Confirm email" is off and password reset needs custom SMTP (Resend + the domain; Supabase > Authentication > SMTP). Auth > URL Configuration must list the live domain.
- Do not use Lemon Squeezy for pure donations; the Ko-fi embed is the chosen route.
- When describing where something is on the site, check the code first (the user was once sent to the book page for a download button that lives on `/account`).
- Site tests drift: `ui-smoke.mjs` once compared the whole checkout response (it gained fields) and filled "every form input" on /contact (the footer newsletter form and the open chat panel also match). Assert the field you care about, scope locators to `main form:has(textarea)`, and `waitForLoadState('networkidle')` before filling (the form re-renders once sign-in is known).

## UI lessons
- Rich-text fields may contain nbsp for every space, which once made a mobile page 2,700 px wide. `src/lib/sanitize.js` converts them, `.dn-prose` has `overflow-wrap:anywhere`, Admin save strips them. Keep these when touching rich-text rendering.
